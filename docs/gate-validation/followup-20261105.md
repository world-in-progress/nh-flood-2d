# astra 审查后的求解器补项

本记录承接 1665cb3，原始证据保留在本目录。新增 `pond_land_type`（本实验 10），塘区库存和通量分类共用同一掩码。配置载入拒绝空塘区、闸塘重叠、缺少任一侧内部接口，以及终态床面高于任一关闸床面的情形；禁用控制器时也校验。高程比较采用实际求解器 F32 表示，避免相同十进制床面与终态被存储舍入误判。

每个闸增加独立的 `channel_budget`，检查

`ΔS_gate = river_net − pond_net + rain − infiltration + positivity + pipe + boundary + rounding + residual`。

闸区源项按实际闸单元累计，不能从河侧与塘侧差额倒推。初始闸库存和累计整数写入检查点，manifest 与 `gate_balance.csv` 同时报告各项和残差。中英文根 README 与参考文档已同步。

## CPU 验证

相关主批 66 项通过、1 项香港慢测入口跳过；随后配置整文件 28 项通过（含新增的 2 项载入防错），合并为 68 项已通过的相关检查。实际香港三路 CPU 比较也已完成，每路 9,054 步，全部八项哈希一致；两个最终候选共用冻结的 c9088166 源码，见 [followup-cpu-hk-v2.json](followup-cpu-hk-v2.json)。机制数据见 [followup-cpu-v2.json](followup-cpu-v2.json)。本轮没有重新执行不受影响的全部历史实验。

新增 7 闸并发算例包含 3,500 个闸单元、跨多个 256 诊断块。一次 CPU 子运行全域残差约 `1.25e-4 m³`，塘区约 `−7.04e-6 m³`，逐闸最大绝对残差约 `3.89e-7 m³`；主批中的全部实际值另保存在 JSON。不同 CPU 归约线程调度可改变末位，不能把这些数值当作所有执行的固定值。

同一 8 m 物理断面分别用一条 8 m 边和两条 4 m 悬挂子边表示。近均衡情形做配对量值比较；干湿阶跃情形同时校验唯一总宽度、各自中心距和 ACC 首步解析量。后者均匀/悬挂中心距为 8/6 m，因此首步流量为 4/3 比值：累计进塘约 `0.001149610/0.001532813 m³`。该差异来自离散梯度，不能声称原始首步流量相同。

干多格通道开启瞬态使用 `dt = 0.125/0.0625/0.03125 s`。首次通水约 `2.75/2.6875/2.625 s`；进塘约 `45.2944/45.5453/45.3116 m³`；出塘约 `37.4715/36.2761/35.5121 m³`；振荡指标约 `111.6856/106.3365/102.9123 m³`。指标是固定输出时刻的塘侧净累计增量变化总量；这是数值细化证据，不是实际工程流量的收敛阶证明。

大时钟测试在正式期 `t = 30000 s` 才给控制点有效超阈水位，核对 1800/3600 s 行程及非整数年龄；没有把 30000 s 设为预热原点。实际 Bnone-I 输入也通过新增接口校验：塘区 126,554 单元、7 个闸；接口宽度、关床面和邻接地类见 [hk-layout-v2.json](hk-layout-v2.json)。这里自动选点只用于映射验证，不是实验的正式控制点配置。

## Metal 验证结果

16:29 的 `pgrep` 检查无求解器 PID 后开始了小规模检查。原版重复两次、无闸和显式禁用四路的小算例物理及预算哈希均相同；之后出现新求解器 PID，香港检查被进程门槛阻止。后续检查在连续六次空闲探测（每次间隔 50 s）后或 20:30 顺序执行，过滤任务之间的短进程空隙。

19:34:13 完成连续空闲确认后，`tests/gate_validation_runset.py` 串行执行的全部 8 个项目均以退出码 0 完成，见 [metal-runset-v2.json](metal-runset-v2.json)。后端为 Metal、设备 Apple M1 Max，Taichi 1.7.4、Python 3.10.17、FastDB 0.2.4、NumPy 2.2.6；完整依赖、系统、输入和验证脚本哈希均在各 JSON。求解器源码统一为 `c908816673c549fee696529f7349d04b51fe6720372837b2c841e019f96f2081`，对应 CPU 实现提交 8ad7562；后续验证脚本变更不改变该源码身份。

详细结果见 [小算例](metal-enabled-small-v2.json)、[中等算例](metal-enabled-medium-v2.json)、[大时钟](metal-late-clock-v2.json)。开启中途的小算例 NumPy/设备床面最大绝对差 `2.384185791015625e-7 m`；中等算例中途逐位相同。完整 1800/3600 s 行程的最大差均为 `9.5367431640625e-7 m`，小于测试前固定的 `4.76837158203125e-6 m` 误差界限。GPU 回放不能笼统称为与 NumPy 逐位相同，这里保留了乘加/除法舍入差异。

另将均匀/悬挂配对推进到第二个水力步，以第一步末的半开床面独立计算无摩阻 ACC 通量参考值，核对新的实际子边通量及库存。CPU 两例通过；Metal 的两种配对及干/湿压力重构读取更新床面的探针，共 4 项新增 pytest 通过，见 [paired-half-open-v2.json](paired-half-open-v2.json)。连同前面的两项完整行程，实际执行的 Metal pytest 共 6 项通过。最后 CPU 配置与兼容小批又通过 30 项检查；这些复测没有重复计入 68 个不同 CPU 用例。

续跑在任何新步骤前恢复的累计整数逐位检查通过。小算例后续累计仍逐位一致；中等算例中途/开启后续跑的最终诊断累计分别出现最高 `3.2741809263825417e-11` / `3.637978807091713e-12 m³` 差异，均在闸区舍入修正项，物理状态和控制事件不变。另固定追加 3 次完整运行，连同原运行及其重复，共 5 次启用参考；跨项最大观测差 `7.275957614183426e-11 m³`，但中途续跑的第 41 项仍超出这 5 次参考在该项的观测幅度。数据见 [启用重复测量](metal-enabled-repeat-spread-v2.json)。本轮没有宣称 GPU 最终预算整数跨独立执行逐位一致，也没有把有限样本幅度当成所有归约调度的上界。

### 兼容与原版重复

小算例先跑原版两次，再跑无闸、显式禁用：全部物理和预算哈希相同，见 [metal-compat-small-v2.json](metal-compat-small-v2.json)。香港实际输入每路均为 9,053 步，原版重复、无闸和显式禁用的 h、q、床面、dt 及完整 trace 哈希全部一致。CPU 的对应 9,054 步结果属于另一个后端的内部对照。香港 Metal 数据见 [metal-compat-hk-v2.json](metal-compat-hk-v2.json)。

香港最初两次原版重复已出现 F32 诊断变化；候选有少数字段超出该两次样本幅度，因此预先固定追加 3 次原版，保留全部 5 次结果。下表以同一原版为锚，列出逐输出时刻的最大绝对差，并另列原版 5 次在同一时刻的最大峰峰值：

### 性能与内存

性能由同步设备图墙钟时间测量，排除前两批；这不包含预处理、编译和主机输出耗时。显存记录采用 Metal SDK 的 `MTLDevice.currentAllocatedSize`，含义是采样到的设备资源分配字节数；M1 使用统一内存，另记进程 RSS 高水位，不将两者混称为独立显存驻留峰值。

在同一 3,850 单元、7 闸合成场景上模拟 120 s，结果见 [metal-performance-v2.json](metal-performance-v2.json)：

| 状态 | 完成步数 | 同步设备图墙钟/步 | Metal 采样资源分配峰值 |
| --- | --- | --- | --- |
| 禁用，第一次 | 266 | 0.212545 ms | 34.4375 MiB |
| 启用并实际开启 | 544 | 0.362121 ms | 35.15625 MiB |
| 禁用，重复 | 266 | 0.213900 ms | 34.4375 MiB |

启用每步耗时为两次禁用均值的约 1.698 倍。启用后的水动力状态也使 CFL 步数增加，因此此比值不等于同一状态下的纯记账开销，更不能直接外推正式全事件运行时长。资源分配峰值增加 0.71875 MiB；控制器自有逻辑字段为 542,296 字节，其中诊断累计器 389,380 字节。池化分配和逻辑字段占用是两种口径，数据同时保留。

## 交付边界

本轮完成了指定 CPU 与 Mac Metal 验证，未启动正式全事件实验、访问 Windows、推送或创建 PR。四网格的正式控制点、统一终态高程来源，以及 gridmen 的床面回放、闸区最大水位排除和溯源适配仍属于实验集成工作；这里的合成控制点和映射用点不能替代它们。GPU 物理状态逐位证据、回放的有限舍入误差及诊断的非逐位现象已分开报告，正式实验是否放行由后续集成审查决定。
